# Excluded File Patterns Reference & Documentation

## Overview
This document provides exhaustive documentation of all file patterns excluded in the root [`.gitignore`](../../.gitignore) for the **SahkaarX Stage Portfolio** repository. The configuration enforces clean repository hygiene, protects secrets from accidental exposure, prevents bloated Git trees, and eliminates cross-platform noise.

---

## Pattern Categories & Architectural Rationale

### 1. Python Environment & Bytecode
Compiled Python bytecode files are dynamically generated by the CPython interpreter at runtime. Committing these files causes merge conflicts, pollutes commit history, bloats repository size, and introduces platform-incompatible binaries.

| Pattern | Match Target | Rationale & Risk of Tracking |
| :--- | :--- | :--- |
| `__pycache__/` | Directory containing `.pyc` and `.pyo` files | Automatically generated on module import. Non-portable across Python versions. |
| `*.py[cod]` | Any `.pyc`, `.pyo`, `.pyd` file | Python bytecode files. Causes unnecessary churn and diff noise. |
| `*$py.class` | Jython compiled classes | Bytecode generated by Java-based Python implementations. |
| `*.so` | Compiled shared objects (C-extensions) | Machine-specific ELF/Mach-O binaries that fail on different architectures. |
| `.Python` | Symlink/marker file in virtual environments | Environment pointer created by legacy virtualenv tooling. |

---

### 2. Python Packaging & Distribution Builds
Packaging artifacts are created during `pip install -e .`, `python -m build`, `python setup.py sdist`, or `wheel` creation. These are derived targets and should never reside in source control.

| Pattern | Match Target | Rationale & Risk of Tracking |
| :--- | :--- | :--- |
| `build/` | Temporary compiler and distribution build dir | Contains intermediate build outputs from `setup.py` / `flit` / `setuptools`. |
| `dist/` | Distribution archives (`.tar.gz`, `.whl`) | Binary package wheels and source distributions. Bloats Git LFS/history. |
| `*.egg-info/` | Setuptools metadata directory | Auto-generated package metadata; rebuilt dynamically on package installation. |
| `wheels/` | Wheels binary cache directory | Pre-built binaries intended for package indexes, not VCS. |
| `*.egg` | Python egg binary distributions | Legacy binary packaging format. |
| `MANIFEST` | File list manifest generated by distutils | Auto-generated during source archive bundling. |
| `pip-log.txt` | Pip execution logging files | Local debugging output from package installation failures. |
| `pip-wheel-metadata/` | Wheel preparation cache | Temporary build directory during wheel builds. |

---

### 3. Virtual Environments & Package Managers
Virtual environments contain isolated copies of Python binaries, standard libraries, and third-party dependencies (`site-packages`). Committing them can add hundreds of megabytes of platform-dependent binaries and break other developers' setups.

| Pattern | Match Target | Rationale & Risk of Tracking |
| :--- | :--- | :--- |
| `venv/` | Default Python virtual environment directory | Standard virtual environment folder created by `python -m venv venv`. |
| `.venv/` | Hidden virtual environment directory | Modern virtual environment folder used by Poetry, VS Code, and Pipenv. |
| `env/` | Legacy virtual environment directory | Common user convention for isolated environments. |
| `ENV/` | Uppercase variant environment directory | Prevents accidental tracking on case-insensitive filesystems (Windows/macOS). |
| `env.bak/` / `venv.bak/` | Backup directories created by scripts | Backup folders left after environment rebuilds. |

---

### 4. Testing, Code Coverage & Linting Caches
Modern Python development tools (pytest, mypy, ruff, tox, coverage) cache syntax trees, analysis databases, and runtime metrics for incremental execution. These caches are local to each developer machine.

| Pattern | Match Target | Rationale & Risk of Tracking |
| :--- | :--- | :--- |
| `.mypy_cache/` | Mypy static type checker cache | SQLite and JSON AST cache files for type checking. |
| `.pytest_cache/` | Pytest session and failure cache | Stores test run states, failure logs, and `cacheprovider` databases. |
| `.ruff_cache/` | Ruff linter/formatter cache | AST cache used by the Ruff linter. |
| `.hypothesis/` | Property-based testing database | Tracks examples found during property-based test executions. |
| `.pytype/` | Google Pytype type inferencer cache | Intermediate type definitions. |
| `.coverage` / `.coverage.*` | Coverage.py measurement data | SQLite database tracking executed code lines per test run. |
| `htmlcov/` | HTML test coverage report output | Multi-file HTML/CSS reports; derived build output. |
| `.tox/` / `.nox/` | Tox/Nox multi-environment test runners | Local virtual environments and test matrices across Python versions. |
| `coverage.xml` / `nosetests.xml` | CI test reports | XML outputs generated for CI/CD ingestion. |

---

### 5. Jupyter & Interactive Computing
Jupyter notebooks create auto-save checkpoints and history snapshots that lead to massive Git diff bloat and merge collisions.

| Pattern | Match Target | Rationale & Risk of Tracking |
| :--- | :--- | :--- |
| `.ipynb_checkpoints/` | Jupyter automatic checkpoint directory | Auto-saved snapshot versions of `.ipynb` files. |
| `*-checkpoint.ipynb` | Named checkpoint notebook files | Checkpoint copies generated by JupyterLab / VS Code Notebooks. |

---

### 6. Environment Variables, Secrets & Sensitive Credentials
Tracking secrets is one of the most severe security vulnerabilities in software engineering. Leaked credentials can compromise cloud infrastructure, databases, and APIs.

| Pattern | Match Target | Rationale & Security Risk |
| :--- | :--- | :--- |
| `.env` | Primary local environment variable file | Contains database URLs, secret keys, API tokens, and passwords. |
| `.env.*` | Any environment-specific configuration file | e.g., `.env.local`, `.env.production.local`, `.env.test`. |
| `!.env.example` | **Whitelist Exception**: Template environment file | Allows committing sanitized template showing required keys without values. |
| `*.pem` / `*.key` / `*.p8` | Cryptographic private keys & certificates | TLS certificates, SSH private keys, Apple developer certificates. |
| `*.cert` / `*.crt` / `*.pfx` | SSL/TLS certificates and PKCS bundles | Digital certificates and keystores. |
| `id_rsa*` | SSH private keys | Personal and machine SSH authentication keys. |
| `credentials.json` | Google Cloud / AWS credential dump | Service account keys and OAuth client secret keys. |
| `secrets.json` | Vault / Kubernetes secret exports | Plaintext API tokens and database credentials. |
| `token.json` / `auth.json` | OAuth2 session refresh/access tokens | User session tokens that allow impersonation. |

---

### 7. Operating System Metadata
Operating systems generate hidden metadata files to store folder viewing preferences, thumbnail previews, and indexing states. These files create clutter and platform-specific merge conflicts.

| Pattern | Match Target | Rationale |
| :--- | :--- | :--- |
| `.DS_Store` | macOS Desktop Services Store | Stores custom attributes and icon positions of folders in Finder. |
| `._*` / `.AppleDouble` | macOS resource fork files | Created when copying files to non-HFS+ file systems. |
| `Thumbs.db` | Windows thumbnail cache | Cache database used by Windows Explorer for image previews. |
| `[Dd]esktop.ini` | Windows folder customization file | Stores custom icon and layout settings for Windows folders. |
| `$RECYCLE.BIN/` | Windows Recycle Bin folder | Temporary directory created on removable or secondary drives. |
| `*~` / `.directory` | Linux backup and KDE metadata | Editor autosaves and file manager directory configs. |

---

### 8. IDEs & Code Editor Workspaces
Personal editor configurations reflect individual developer settings (zoom level, cursor position, active tabs, open files) and must not be forced upon other contributors.

| Pattern | Match Target | Rationale & Exception Strategy |
| :--- | :--- | :--- |
| `.vscode/*` | Visual Studio Code directory | Ignores user-specific workspace history and debug cache. |
| `!.vscode/settings.json` | Whitelisted team VS Code settings | Permits committing shared formatter/linter rules. |
| `!.vscode/launch.json` | Whitelisted team debug configurations | Permits committing shared debug runner targets. |
| `!.vscode/tasks.json` | Whitelisted team automation tasks | Permits committing shared build and test tasks. |
| `.idea/` | JetBrains IDE workspace (PyCharm, WebStorm) | Contains developer workspace states and local inspection data. |
| `*.swp` / `*.swo` / `*.swn` | Vim swap and recovery files | Created by Vim during active editing sessions. |
| `*.sublime-project` | Sublime Text project metadata | Local editor project definitions. |

---

### 9. Logs & Temporary Scratch Files
Local runtime logs, temporary debug files, and developer scratch pads must remain outside version control.

| Pattern | Match Target | Rationale |
| :--- | :--- | :--- |
| `*.log` / `logs/` | Application log output files | Continuously updated runtime logs that balloon Git history. |
| `*.tmp` / `*.temp` / `*.bak` | Temporary and backup files | Created by editors, formatters, and utility scripts. |
| `scratch/` / `tmp/` | Developer scratchpads | Folders reserved for rapid experimentation and testing notes. |

## Pattern Testing & Verification Commands

Developers can verify that any specific file path is properly excluded by running the Git diagnostic command:

```bash
# Check why a path is ignored (outputs matching rule and line number):
git check-ignore -v <path-to-file>

# Examples:
git check-ignore -v .env
# Output: .gitignore:70:.env    .env

git check-ignore -v src/__pycache__/logger.cpython-310.pyc
# Output: .gitignore:9:__pycache__/    src/__pycache__/logger.cpython-310.pyc

git check-ignore -v .venv/bin/python
# Output: .gitignore:34:.venv/    .venv/bin/python
```

To verify that `.env.example` is correctly permitted (not ignored):
```bash
git check-ignore -v .env.example
# Expected Output: (No output, exit code 1 = file is NOT ignored)
```
